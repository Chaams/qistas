Qistas

القسطاس

La balance qui pèse chaque pull request et la bloque quand votre chatbot arabe se dégrade.

Qistas fait passer votre bot sur des cas réels en dialecte, en arabizi et avec des données régionales, note les réponses avec un juge LLM et des règles, puis compare avec la version précédente. Une seule fuite suffit à arrêter la PR.

Le problème

Un bot arabe échoue de façons qu'aucun outil générique ne mesure

Promptfoo, DeepEval ou Braintrust évaluent très bien un bot en anglais. En arabe, les pannes sont ailleurs : le registre, l'écriture, les identifiants locaux.

Comment ça marche

Quatre étapes à chaque pull request

La GitHub Action lance le bot construit à partir de la PR, l'évalue, puis commente la PR avec le verdict.

  1. 1 · cas

    Les questions

    Des fichiers YAML lisibles par un QA : dialecte attendu, réponse de référence, attaques à refuser.

  2. 2 · bot

    Votre chatbot

    Appelé en HTTP, sur plusieurs tours. Ses réponses et les documents qu'il a retrouvés sont collectés.

  3. 3 · juge

    La notation

    Un juge LLM, avec votre propre clé, plus des règles : arabe normalisé, PII régionales, contrôle de Luhn.

  4. 4 · gate

    Le verdict

    Seuils, comparaison avec baseline.json, et blocage sur toute faille de sécurité.

Prêt.

Essayer

Installer

En local ou dans GitHub Actions

En local

pip install "qistas[gemini]"   # ou [anthropic], [openai]
qistas init
qistas run
qistas gate results.json

Dans une pull request

- uses: Chaams/qistas@v1
  with:
    target-url: ${{ steps.preview.outputs.url }}
  env:
    GEMINI_API_KEY: ${{ secrets.GEMINI_API_KEY }}
